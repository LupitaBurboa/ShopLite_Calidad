# ShopLite Data Model

## 1. Persistence

ShopLite serves its interface and API through Node.js and Express. `frontend/db.js` is the browser's HTTP client; `backend/server.js` validates operations and accesses SQLite. The persistent database is created at `data/shoplite.sqlite`.

The following tables match the SQL schema automatically created by `backend/server.js`. IDs are auto-incrementing integers, and timestamps are stored as text generated by SQLite.

| Table | Purpose |
| --- | --- |
| `users` | User accounts and password hashes |
| `products` | Product catalog and inventory |
| `cart_items` | Cart items by user and product |
| `orders` | Order headers and shipping addresses |
| `order_items` | Purchased line items |

## 2. Business tables

The types below are SQLite types. The API converts columns into JSON objects for the browser. PK means primary key; FK means foreign key.

### `users`

| Field | Type | Constraints / description |
| --- | --- | --- |
| `id` | `INTEGER` | Auto-incrementing PK. |
| `name` | `TEXT` | User's display name. |
| `email` | `TEXT` | Unique email; duplicate checks are case-insensitive. |
| `password_hash` | `TEXT` | bcrypt hash; the original password is never stored. |
| `role` | `TEXT` | `admin` or `user`; defaults to `user`. |
| `created_at` | `TEXT` | UTC date and time generated by SQLite. |

### `products`

| Field | Type | Constraints / description |
| --- | --- | --- |
| `id` | `INTEGER` | Auto-incrementing PK. |
| `name` | `TEXT` | Product name. |
| `description` | `TEXT` | Product description. |
| `price` | `REAL` | Unit price. |
| `stock` | `INTEGER` | Available units; reduced on purchase and never below zero. |
| `category` | `TEXT` | Product category. |
| `image` | `TEXT` | Image URL or local path, such as `/images/example.png`. |
| `created_at` | `TEXT` | UTC date and time generated by SQLite. |

### `cart_items`

| Field | Type | Constraints / description |
| --- | --- | --- |
| `user_id` | `INTEGER` | Part of the composite PK and FK to `users.id`; cascades on delete. |
| `product_id` | `INTEGER` | Part of the composite PK and FK to `products.id`; cascades on delete. |
| `qty` | `INTEGER` | Positive product quantity. |

Composite primary key: (`user_id`, `product_id`).

### `orders`

| Field | Type | Constraints / description |
| --- | --- | --- |
| `id` | `INTEGER` | Auto-incrementing PK. |
| `user_id` | `INTEGER` | FK to `users.id`. |
| `subtotal` | `REAL` | Item amount before tax and shipping. |
| `tax` | `REAL` | Tax calculated by the server. |
| `shipping` | `REAL` | Shipping cost. |
| `total` | `REAL` | Total: subtotal + tax + shipping. |
| `status` | `TEXT` | Order status; defaults to `paid` (simulated payment). |
| `shipping_full_name` | `TEXT` | Recipient's full name. |
| `shipping_address` | `TEXT` | Street address. |
| `shipping_city` | `TEXT` | City. |
| `shipping_zip` | `TEXT` | ZIP or postal code. |
| `shipping_country` | `TEXT` | Country. |
| `created_at` | `TEXT` | UTC date and time generated by SQLite. |

### `order_items`

| Field | Type | Constraints / description |
| --- | --- | --- |
| `id` | `INTEGER` | Auto-incrementing PK. |
| `order_id` | `INTEGER` | FK to `orders.id`; cascades on delete. |
| `product_id` | `INTEGER` | FK to `products.id`; set to `NULL` if the product is deleted. |
| `name` | `TEXT` | Product name saved as a historical snapshot. |
| `price` | `REAL` | Unit price saved as a historical snapshot. |
| `qty` | `INTEGER` | Positive purchased quantity. |

## 3. Sessions and seed data

Authentication uses an HTTP-only `shoplite.sid` cookie managed by `express-session`. In local mode, session data is stored in memory and is lost when the server restarts; accounts, products, and orders remain in SQLite. `sessionStorage.lastOrderId` temporarily stores the ID used by the order confirmation page.

The server seeds sample products when the `products` table is empty. It also creates the demo accounts `admin@shop.com` (role `admin`) and `user@shop.com` (role `user`) if they do not exist. Their passwords are `admin123` and `user123`, stored using bcrypt.

## 4. Relationships and behavior

- A user can have many orders and cart items: `orders.user_id` and `cart_items.user_id` reference `users.id`.
- A cart has at most one row for each user and product combination.
- `order_items` separates purchased lines from the order header. It stores the product name and price at purchase time, even if the product is later edited or deleted.
- Foreign keys are enabled. Deleting a product removes its cart rows and preserves previous orders with `order_items.product_id = NULL`.
- Checkout validates stock and calculates amounts on the server within a transaction: 8% tax, shipping of 5.00 when the subtotal is below 75.00, and free shipping at or above 75.00. The same transaction records the line items, reduces stock, and clears the cart.
- Payment is simulated. The server does not receive or store card numbers, expiration dates, CVVs, or last digits.
- `data/shoplite.sqlite` contains persistent data and is excluded from Git. Do not use the default session secret or in-memory session store in a public deployment.

## 5. Main files

- `backend/server.js`: SQLite schema, seed data, authentication, and API endpoints.
- `frontend/db.js`: browser-side `fetch` client for the API.
- `frontend/checkout.js`: shipping form and order submission.
- `frontend/admin.js`: catalog, user, and order administration.

## 6. Installation and running

### Requirements

- Node.js LTS and npm.
- A terminal opened in the project root folder.

Check that they are available:

```powershell
node --version
npm --version
```

### Install dependencies and start the server

From the project folder, run:

```powershell
npm install
npm start
```

Open `http://localhost:3000` in your browser. Express serves both the interface and the API; do not open `index.html` directly or use Live Server. To stop the server, return to the terminal and press `Ctrl+C`.
